# 医生预约域改造方案

- **改写后的任务**：把已经合入的面试预约垂直 Bot，整域改成可演示的「病人约医生档期」：医生只被动提供出诊时段，系统按科室匹配空闲医生、占档、改期。候选人改为患者，面试官改为医生，岗位改为科室/专长，轮次改为就诊类型（初诊/复诊/咨询），线上线下改为门诊/互联网医院。有界工具环、按请求隔离的 session、改期再查、对话轮数预算、状态机，以及已经拆掉的伪 MCP，全部保留，只换域语义。做完后，审查者要能决定这套演示还能不能诚实写进简历：它仍是垂直预约，不是 HIS，不诊断、不处方。本文件只交付这份可执行合同；Phase 2 等确认后再改代码。

- **要用的方法和工具**：
  - 高度。看完要做的决定是「换域之后，控制面三句实话还在不在、医疗宣称有没有越界」。任务抬到这份对着现有符号的换域合同，而不是空泛的「做成医疗 AI」。合同能在当前仓库里用离线 pytest 验证。
  - 深度，从代码原件入手，不从第二手摘要入手。现状锚点：`db/models.py` 的 `Interviewer` / `InterviewerSchedule` / `Interview` / `CandidateBehavior` / `CandidatePreference` / `CandidateRecommendation` / `KnowledgeDocument` / `SessionSlotSnapshot`；`agents/interview/interviewer_tools.py` 的 `find_interviewer`、`FIND_INTERVIEWER_SCHEMA`、`TOOL_ARGUMENT_KEYS`、`TOOL_STATUSES`、`_validate_arguments`；`agents/interview/booking_tool_loop.py` 的 `ALLOWED_ACTIONS`、`MAX_INVALID_ATTEMPTS = 3`、`policy_next_action`、`ToolLoopFallback`、`ToolLoopTimeout`；`agents/interview/alternative_slots.py` 的 `search_alternative_slots`；`agents/interview_agent.py` 的 `MAX_TURNS = 12` 与 `run_stream`；`agents/session_registry.py` 的 `new_interview_history` 与 `SLOT_FIELDS`；`agents/task_classification/state_manager.py` 的 `can_transition_to`；`agents/task_classification_agent.py` 里 `depth >= 1` 只走 `UnrelatedHandler`；`services/interviewer_service.py` 的 10 人种子；`services/knowledge_service.py` 的 8 条 `default_knowledge`；`services/interview_service.py` 的 `POSITION_DEPARTMENT_KEYWORDS`。离线模型继续用 `langchain_core` 的 `FakeListChatModel`。真模型只走 `config/model_provider.py` 的 `create_chat_model`。
  - 名词与模型。患者只保留演示姓名，对应现在的 `candidate_name`，不建病历主表（与现在「候选人不建主表」同一取舍）。医生对应 `interviewers`：`department` 从招聘方向改为科室，`bio` 只放专长关键词，供同科室相似度推荐。科室/专长对应现在的 `position`：用户原话进槽位，筛选仍是「科室 + 该时段空闲」。就诊类型对应 `round`，只影响默认时长和文案，不参与筛选（对齐 README 里「轮次不参与筛选」）。渠道对应 `mode`。已采纳的枚举：就诊类型初诊 30 分钟、复诊 15 分钟、咨询 20 分钟，认不出时默认 30 分钟；渠道默认「门诊」，「视频/线上/远程」归互联网医院，「线下/到院/现场」归门诊。科室六类：内科、外科、儿科、皮肤科、口腔科、全科。只匹配用户说出的科室词；只说症状、不说科室时走 `ask_user` 请其选科室，不做症状分诊。`StateEnum.INTERVIEW = "interview"`（`config/constants.py`）与 `TaskClassifier.VALID_CATEGORIES` 里的 `interview` 改为 `appointment`；`query` / `consult` 保留。转移表仍是分类态进出预约态、分类态进出咨询态。

`agents/appointment/`：`interview_processor.py`→`appointment_processor.py`，`interviewer_finder.py`→`doctor_finder.py`，`interviewer_tools.py`→`doctor_tools.py`（`find_doctor`、`FIND_DOCTOR_SCHEMA`），`interview_database.py`→`appointment_database.py`；`booking_tool_loop.py`、`alternative_slots.py`、`input_parser.py`、`message_builder.py` `new_interview_history` 改为 `new_appointment_history`，键改为 `patient_name`、`specialty`、`visit_type`、`channel`、`doctor_name`、`recommended_doctor`、`original_doctor`。表：`interviewers`→`doctors`，`interviewer_schedules`→`doctor_schedules`，`interviews`→`appointments`（`patient_name`、`specialty`、`visit_type`、`channel`、`doctor_id`），`candidate_behaviors` `/api/patient_analysis`；`/api/consultation`、`/api/knowledge`、`/api/task`、`/chat`、`/chat/stream` 路径保留，标签和分类词改为预约。页面：`/interviewer`→`/doctor`，`/interviewer_schedule`→`/doctor_schedule`，`/candidate_analysis`→`/patient_analysis`；模板 `interviewer.html`、`interviewer_schedule.html`、`candidate_analysis.html` 随路由改名；`index.html`、`admin_dashboard.html`、`knowledge_management.html`、`database_admin.html` 留文件名，改文案、表名和统计键（现为 `appointment_test.db`，`FakeInterviewService` 改为 `FakeDoctorService`（`get_doctor_by_name` 等与医生仓库同名）。`services/recommendation_service.py` 只改到诊提醒文案，调度入口保留。回复前缀由 `[REPLY][面试机器人]` 改为 `[REPLY][预约助手]`。种子：删掉旧库 `data/interview_agent.db`（若存在），新建 `sqlite:///data/doctor_appointment.db`。`KnowledgeService.initialize` 只在空库写入，`initialize_default_interviewers` 是幂等补人，沿用旧文件会留下「张伟 / 一面」；FAISS 是 `APPOINTMENT_DB_PATH`（`config/database.py`、`api/core/deps.py`）。10 位医生人数对齐现种子 3/2/2/1/1/1，姓名用虚构的陈安、林夏、周宁（内科），吴凯、郑朗（外科），苏晚、何川（儿科），许清（皮肤科），马宁（口腔科），丁一（全科）；`bio` 以「演示人设，非真实医师」开头，只写科室匹配词。8 条 FAQ 换成 8 条就诊须知：预约步骤、就诊类型只影响时长、互联网医院的网络与摄像头、门诊演示地址与提前到场、携带物品但不入库、改期文案（提前 24 小时、同一预约最多一次）、到诊提醒、演示不收费且没有支付工具。`agents/consultant/prompt_builder.py` 与 `agents/task_classification/task_classifier.py` 的示例从「张伟 / 一面 / 后端」改为「丁一 / 初诊 / 内科」。Phase 2 同步改 `README.md` 与 `.env.example`。
  - 控制面保留，简历只写换域后仍然为真的句子。模型每轮仍只能选 `ask_user`、`find_doctor`、`finish`。参数仍由 `_validate_arguments` 要求键集合恰好等于 `specialty`、`start_time`、`duration_minutes`、`doctor_name`。`invalid_arguments` 连续非法仍以 `MAX_INVALID_ATTEMPTS`（3）为上限，超时走 `ToolLoopTimeout`，两者都回退 `run_stream`。`TOOL_STATUSES` 六个字符串不改：`available`、`unavailable`、`not_found`、`no_match`、`invalid_arguments`、`invalid_time`。`no_match`，或 `unavailable` 且 `alternatives` 为空，仍调用 `search_alternative_slots`：未来两个工作日、时长用就诊类型默认值、最多两个选项，用户选定后再查一次医生。`ChatRequest.session_id`、按 session 分的历史与 `session_slot_snapshots` 保留；`api/chat_handler.py` 继续没有 `global_session_id`。`MAX_TURNS = 12` 到点报出已收集槽位并停止。`set_state` 仍必须先过 `can_transition_to`，非法抛 `IllegalStateTransition`。无关深度 `>= 1` 只走 `UnrelatedHandler` 固定回复。聊天流只留 `[REPLY]`，`[THOUGHT]` 留在日志。不恢复 `WeatherMCPTool`、`AgentExecutor`，提示词里不出现 `pay` / `statistics`。简历可以写的三句：动作空间只有这条垂直预约环；会话按 `session_id` 隔离并能从 SQLite 恢复缺槽和是否在等确认；名词与表一致，说的是约医生档期。简历不能写：诊断、处方、分诊准确率、临床决策、完整 HIS、号源池、叫号、缴费、电子病历、检验检查、医保、真实医院或真实患者、等保或 HIPAA 合规、任意工具的 MCP 医疗插件、非流式已打通 stream-only 网关，也不能再写「候选人匹配面试官」或「招聘方向」。
  - 合规边界。页面页脚、咨询系统提示、成功文案共用一句：「本系统是预约演示，只帮助选择科室、就诊类型和医生档期，不提供诊断、处方或急救建议。紧急情况请前往线下医疗机构或呼叫急救电话。」咨询里出现症状判断、用药、剂量时，固定拒绝并引回预约，不进知识库编造。不新增、不采集、不在文案里暗示这些字段已经存在：诊断、处方、剂量、过敏史、病历号、身份证号、手机号、检验结果、治愈率、专家排名、医保、缴费。患者只留演示姓名。种子医生与门诊地址标明虚构（「演示园区」），不写真实医院名。
  - 广度。交付物要完成的动作，是让看演示的人十秒内听清「这是约档期，不是看病」。组队五人，每人一句方法：预约工程师对照 `BookingToolLoop` 与 `TOOL_STATUSES` 核对动作合同没有加宽；数据工程师用空库启动核对 10 位医生与 8 条就诊须知，并确认旧 SQLite 不会被读到；合规审阅人用「这是什么病、开什么药」两句问咨询，核对固定拒绝；测试工程师把下面的 pytest 断言从面试名词改到医生名词；挑错人把 README 和简历草稿逐句对着代码，代码里没有的句子删掉。
  - 范围。仍是垂直预约 Bot。Phase 2 不建排班模板、号源池、叫号、缴费、病历、检查检验、随访病历，也不做「医生筛选患者」。医生侧只有档期被占用和释放。

- **野心目标**：换域之后，审查者仍只用离线 pytest、不靠真模型，就能核对三句实话：垂直预约环还在、多会话还在、页面和表里没有任何诊断或处方。

- **需要用户提供的**：本阶段和离线 pytest 不需要密钥，也不需要真实病历。下面四条若与已采纳假设不同，请给替换表；不回复就按文档里的枚举、虚构医生、新库路径、不留旧 URL 执行。一，科室是否就用内科/外科/儿科/皮肤科/口腔科/全科，时长是否就用初诊 30、复诊 15、咨询 20，默认渠道是否就是门诊。二，是否要保留 `/api/interviews` 等旧路径别名（默认不留）。三，若种子要用指定医院名或医生真名，需说明其为虚构或已获授权；否则用文档中的虚构姓名与「演示园区」。四，以后做真 LLM 联调时，提供已有的 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`（或 Azure 对应变量）；那次联调才要处理 stream-only 网关，本阶段不改调用代码。
